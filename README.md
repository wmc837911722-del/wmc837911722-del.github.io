## 我主要解决的问题

很多 AI 项目并不是缺少模型，而是卡在了业务与工程之间：

- 有不少 AI 想法，但无法判断哪个场景值得优先投入
- 原型能够演示，却接不上真实数据、权限和业务系统
- 业务需求、产品方案与工程实现之间缺少统一语言
- 项目上线前缺少效果评测、安全边界和稳定性保障
- 系统已经上线，但没有形成反馈、优化和持续采用闭环

FDE 的工作，就是进入这些不确定性中，把模糊问题拆成可验证任务，再把验证有效的方案做成可以进入生产的系统。

## 我能够提供的服务

### 01｜业务诊断与方案共创

和业务负责人及实际使用者一起梳理目标、流程、约束和成功标准，找到 AI 最有价值、也最适合落地的切入点。

可能交付：

- 业务问题、目标与成功标准定义
- 用户流程和关键痛点梳理
- AI 机会、限制与风险清单
- 解决方案架构与实施路径
- 项目范围、优先级和阶段目标建议

### 02｜AI 原型与智能体验证

把模型、工具和业务数据组合成可操作的原型，用真实场景尽早验证关键假设，避免在尚未证明价值前投入完整开发成本。

可能交付：

- AI 工作流或智能体原型
- 工具调用与数据接入验证
- Prompt、上下文和流程设计
- 效果评测方案与验证记录
- 安全边界、失败场景和改进建议

### 03｜生产集成与工程交付

将验证通过的方案接入现有前端、后端、数据、权限和企业系统，完成从原型到生产环境的关键工程工作。

可能交付：

- Web 产品或内部业务工具
- 前后端功能与业务接口
- 模型、知识库及企业系统集成
- 权限控制、日志与异常处理
- 测试、部署、监控和交付文档

### 04｜落地采用与持续迭代

围绕真实使用结果持续调整产品体验、业务流程和模型能力，让系统不仅能够上线，也能够被团队使用和维护。

可能交付：

- 使用反馈与问题复盘
- 产品、流程和模型优化方案
- 版本迭代与效果再评测
- 运维、使用和交接文档
- 团队能力沉淀与知识转移

## 特别适合这些团队

- 已经发现 AI 应用机会，但还没有形成清晰落地方案
- 希望为现有 SaaS、内部系统或业务流程增加 AI 能力
- 已经拥有演示原型，但卡在数据、集成、权限或上线阶段
- 需要连接业务、产品和工程的综合型交付角色
- 希望通过小范围验证控制风险，再决定是否扩大投入
- 需要的不只是代码，而是一条从问题到生产结果的闭环

## 合作方式

可以从一次问题诊断、一个可验证原型开始，也可以覆盖完整的产品开发与生产交付。

- **单次诊断与方案共创**：梳理场景、目标、约束和落地路径
- **阶段性项目交付**：围绕明确目标完成原型、集成或上线
- **联合产品研发**：和业务、产品及技术团队共同推进完整方案
- **阶段性技术顾问**：针对架构、AI 工作流、评测和工程交付提供支持

具体范围、周期、验收方式和报价，以实际项目评估为准。

## 合作流程

1. **初步沟通**：了解业务场景、当前问题、期望结果和计划时间。
2. **问题诊断**：梳理用户流程、数据条件、现有系统和主要约束。
3. **范围确认**：共同确认阶段目标、交付内容、验收方式、时间安排和合作报价。
4. **分阶段交付**：按“发现问题—构建原型—真实验证—生产集成”的路径推进。
5. **上线与迭代**：根据真实使用反馈继续优化，并完成必要的文档和团队交接。

## 我的工作原则

- 从业务结果出发，而不是为了使用 AI 而使用 AI
- 先验证最关键的不确定性，再扩大工程投入
- 尽早讨论数据、权限、安全、成本和维护问题
- 让方案能够被真实用户采用，而不只是完成演示
- 让过程、决策和交付物可检查、可交接、可继续迭代

### 本地开发

需要 Node.js `>=22.13.0`。

```bash
npm install
npm run dev:github-pages
```

### 构建与检查

```bash
npm run build:github-pages
npm run preview:github-pages
npm run lint
npm test
```

`app/page.tsx` 与 `app/globals.css` 是两套部署共同使用的页面源码。推送到 `main` 后，GitHub Actions 会自动构建并发布。
